# 抢先版验收维护约定

2026-11-09 独立审查确认：首版抢先版实现中的三处问题在启用前修复。以下约定由对应回归测试守住。

- 考勤页按区分大小写的完整代理提示识别拦截；登录状态按重定向后的登录网址判断。普通页面中的脚本、历史记录和登录提示属于业务内容。考勤请求使用 `persist:company-forum` 分区的会话，复用已有登录态。
- 考勤域名与页面状态继续保留在报告和提示中；取得真实机器样本前，它们作为提示项，独立于转正必过项。其他失败项保持拦截。
- 签名运行库指纹只保留位置类别。所有回传文本通过统一脱敏函数，兼容正常路径、8.3 用户目录别名与 JSON 转义路径。
- 更新保持原有六小时周期，体检定时器不额外发起更新检查。自家更新地址被拦时，检查保留原有后台无感放行一次并重试；下载先尝试后台放行，仍被拦时沿用交互放行再下载。
- 现有远程 `update` 包含下载和后续重启，`status` 仅读取状态；当前未提供只检查更新的远程指令。候选版依靠下次六小时检查或手动检查，不增加远程接口。

根因与影响：首版采用宽泛的页面关键字识别，可能把正常页面当成拦截或登录页；运行库绝对路径可能绕过仅匹配长用户名的脱敏；五分钟轮询叠加自动放行可能形成持续点击。回归分别覆盖页面内容与最终 URL、分区会话、考勤提示判定、位置类别与短名脱敏、后台放行和六小时调度。

测试入口：`tests/unit-canary.test.js` 中的 P1-1/P1-2/P1-3 用例，以及报告接收端 `unit-canary-reports.test.js` 的考勤提示回归。

2026-11-09 总负责人修正 P1-3 范围：原任务书将后台放行限制扩大到了所有用户，导致普通成员后台检查及下载的既有放行流程退化。风险通过保留六小时节拍、取消体检额外检查解决；控制器放行逻辑恢复至 bd05f0b。新增两条默认关闭场景的恢复回归，分别验证 silent 检查放行重试和下载后台放行失败后的交互放行重试；其他抢先版修复保留。
