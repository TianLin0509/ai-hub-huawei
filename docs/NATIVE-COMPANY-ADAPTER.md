# 内置公司模型适配

成员版与公开版共用。装好并登录 CodeAgent 后，公司模型接入使用 Hub 内置适配层，不再要求另外取得适配器压缩包。

## 首次启用

Hub 读取 CodeAgent 的安装版本和区域缓存。区域尚未确认时，通过身份服务的区域信息接续；仍未确认则在公司模型设置里选择蓝区、绿区或黄区，不自动猜一个区域。

首次初始化在后台运行一次 CodeAgent，取得与安装版本匹配的签名时间戳，并在 Hub 自己的数据目录保留 CodeAgent 释放的两个必要运行库文件。正常后续启动复用这些本机文件；CodeAgent 升级后重新初始化。运行库由本机已安装的 CodeAgent 提供，Hub 发行包不包含这些二进制文件或登录凭据。

部分 CodeAgent 版本将运行库释放到安装目录的 `temp/codeagent`，不使用此次初始化的临时目录。Hub 会在结束自己启动的 CLI 前查询该进程实际加载的运行库，并保留同目录的完整文件对；不会按修改时间选择历史缓存。取得签名信息后若运行库保留失败，界面会单独说明这一原因。

## 兼容与协议配置

既有上游自定义配置优先；明确指定旧适配包的配置继续使用旧加载路径。旧包自动找到时仍可读取其中的上游参数，但签名默认采用 Hub 内置实现。

没有旧包的新安装使用 `core/company-proxy/native-protocol.json` 中经产品负责人确认的最小协议配置。公共审计按指定文件、字段和精确值登记这些固定项；未知地址、变化的路径或参数、其他文件中的同一地址以及凭据仍会被检查。共享发行审计也必须同步更新并通过，不能跳过检查后发布。

“组件已就绪”只表示安装和本地检查通过。真实账号能否调用模型仍以一次真实请求的结果为准。初始化失败会显示原因，不用推测版本号或当前时间冒充 CodeAgent 的真实信息。

## 开发验证

`tests/unit-native-signer.test.js` 验证 DLL 调用约定、错误处理、签名输出检查和运行库文件保留；`tests/unit-company-model-proxy.test.js` 验证首次初始化、配置优先级与区域选择。FFI 替身的单测不能代替公司电脑上的真实 DLL 和模型请求验证。
