# 通知与后台终端入口复核（2026-11-22）

## 本轮修复

通知开关检查过去只在桌宠分流内，Windows toast、托盘气球没有共用它；桌宠里已经显示或排入队列的旧通知也不会随着关闭设置而撤下。本轮统一补上这些检查。普通桌面卡与桌宠分流之前增加去重，撤回后的异步显示请求不能重新弹出。通用子进程工作线程和主线程兜底强制隐藏控制台，并补齐遗漏的启动选项。

保留默认设置、要紧提醒、历史圆点、用户主动打开的 GUI、CLI 显式配置和原来的提醒去处。没有增加界面文案或修改默认通知档位。

## 入口逐项结论

| 入口 | 开关、去重与焦点结论 |
| --- | --- |
| 普通会话、网页会话 | 经 `desktop-notification:show` 到桌面控制器，主进程先检查回执策略再分流；稳定事件按会话、类别、时间/通知 ID 去重，无时间的同文 15 秒限流；最多记录 2048 条。只用 `showInactive`，不会因完成通知抢输入焦点。 |
| Hub 助理到点提醒、联动通知、公司助理提醒 | 直接调用相同的桌面控制器，同样覆盖开关、去重和异步撤回保护。到点提醒按原定义属于要紧提醒。 |
| 桌宠通知卡 | 桌面控制器在路由前去重。提醒总线按 ID 去重，SpeechQueue 另有最多 2000 条 ID 去重。设置变化后重新检查当前和待显示通知；普通旧气泡立即转为历史圆点，改用小卡时桌宠也不再说旧通知。 |
| 桌宠闲聊、成长演出与版本提醒 | 各自受桌宠模式、每日/每版本记录限制，保留原来的独立设置。磁盘与成长事件保留原来的例外。 |
| Windows 原生 toast | 业务源码只有账号网络出口状态变化一处；原有状态变化去重保留，新增桌面回执策略检查。普通恢复提示可关闭，网络故障仍按原定义属于要紧提醒。未在真实账号网络上触发系统 toast。 |
| 托盘气球 | 用户关窗后的说明，每次 Hub 生命周期最多一次；新增回执关闭检查。关闭说明不影响藏入托盘、点击图标恢复。 |
| 闪烁与抢焦点 | 没有业务 `flashFrame` 入口。显式 focus 来自用户定位会话、托盘/实例切换、浏览器登录、桌宠输入框/菜单、退出失败恢复；不从普通完成提醒调用。 |
| CLI 自带提醒 | 主干 `1034602be`、`b5ff147f0` 已修复，跳过重做。auto/hub/own 三档仍保持；auto 在 Hub 回执关闭且桌宠未开时会保留 CLI 自带提醒，显式环境变量优先，影响之后新开/重启的会话。 |
| 更新与多开提示 | 属于更新、托盘、多开各自的设置，未合并进回执开关。更新按版本持久化去重；多开只提示更早启动的实例，主干 `54cbbb40e` 已修复，跳过重做。 |
| 会话底部“通知开/关” | 只控制飞书完成通知，标题明确写明飞书；不是桌面总静音开关。 |

## 子进程覆盖

已全仓检索 child_process 和启动调用，回归守卫扫描根目录及 main/core/scripts/renderer 的 JS/CJS/MJS，跳过依赖、供应商代码与链接目录。工具是面向当前 CommonJS 写法的轻量词法守卫，不是通用 JavaScript 语义分析器；字符串里的脚本文本不当作当前模块的调用。

补齐处：`core/off-main-exec.js`（工作线程与主线程兜底）、`core/network-egress-monitor.js`、`core/personal-chrome.js`、`core/cli-tools/installer.js`、`core/codeagent-serve.js`、`core/company-assistant/ppt-map-model.js`、`core/owned-process.js`、`scripts/publish-release-assets.js`。

5 处原来明确用于主动打开 GUI 的调用精确登记：专用账号登录浏览器 2 处、PPT Doctor 1 处、按 visible 参数打开的浏览器 2 处。没有把主动登录窗口改成不可见。是否要求这些 GUI 也一律 windowsHide=true，需要产品负责人决定。

## 留给产品负责人的决定

现有“关闭”选项明确说明仍保留要紧提醒；会话飞书通知与 CLI 自动档也有独立语义。若目标是一个全部静音的总开关，需要统一这几处交互与说明。本轮按原有定义修复缺口，未自行改变这条产品规则。
